# kg-idea · 灵感记录

## 定位：还没想清楚的东西

| | kg-capture | **kg-idea** |
|---|---|---|
| 输入 | 踩过的坑、做过的决策、验证过的边界 | 一个念头，还说不清 |
| 状态 | 已有结论 | **没有结论** |
| 价值 | 半年后遇到同样问题能翻出来 | 现在看着有点意思，可能长成东西 |
| 出口 | 直接写 `wiki/` | 先进 `ideas/`，想清楚了才毕业到 `wiki/` |

**判断标准**：他说的这句话，是在告诉你一个事实，还是在抛一个可能性？
后者走本 skill。

## 铁律：先落盘，再追问

**灵感最怕的是被打断。** 他正在想一个东西的时候，你问"这个跟你之前记的
xx 有关系吗"——他的思路就断了，而且可能因为答不上来就放弃了这个想法。

所以顺序是死的：

```
1. 立刻落盘（不问任何问题）
2. 告诉他记下了，在哪
3. 然后才问一到两个问题
4. 他答了就补进去，不答就算了 —— 那也是一条完整的灵感
```

**绝对不要**在落盘前问"你想记成什么标题"、"这个属于哪个主题"。
标题你自己起，主题你自己判断，错了以后能改。

## 落盘

先运行 `../bin/kg-py kg-vault/scripts/vault_cli.py list --json`，按灵感主题与 `desc`
自动选择库。多库时给下面命令在子命令前加 `--vault <path>`；不要使用默认库代替分类，
也不要为选库打断用户。

```bash
../bin/kg-py kg-idea/scripts/idea.py --vault <path> new "标题" \
  --body "用你的话把他的想法说清楚，一两段" \
  --topics "产品,AI" \
  --quote "他当时说的原话" \
  --source "什么场景下想到的"
```

**标题**：短，是这个想法的核心，不是描述。
`用 Flutter 重写播放器` 而不是 `关于要不要用 Flutter 重写播放器的想法`。

**正文**：把他那句零碎的话补成能看懂的一两段。他说
「如果日报通知能反选」，你要写清楚"反选"解决的是什么问题
（判断有了反馈闭环，不用每天重新猜）。**这是你的加工，不是复述。**

**原话必须留。** 三个月后他回看，自己那句原话比你的整理更能唤起当时的感觉。

**关联**：`--links "另一个灵感,还没写的某个想法"`。
指向不存在的页也可以 —— 那就成了「幽灵」，是待展开的线索。

## 追问：一到两个，不能更多

落盘之后再问。问什么取决于这个灵感缺什么：

| 灵感的问题 | 该问的 |
|---|---|
| 概念含糊 | 「反选是指手动标某条，还是让我记住这类不提？」 |
| 可能和旧想法重复 | 「这跟你 8-07 记的『通知交给 AI 判断』是同一件事的延伸吗？」 |
| 动机不清 | 「是想解决什么问题，还是纯好奇？」 |
| 边界不清 | 「只针对通知，还是消费、健康也想这样？」 |

**不要问他"这个重要吗"、"要不要展开"** —— 那是让他替你做判断。
也不要问超过两个，问多了他不想答，下次就不跟你说灵感了。

他答了：

```bash
../bin/kg-py kg-idea/scripts/idea.py append "标题" \
  --section "追问" --body "问：xxx\n答：xxx"
```

他不答（或者答了句"再想想"）：**就这样，不要追**。
一条只有原始念头的灵感也是完整的。

## 回看

```bash
idea.py list [--days 30]     最近的灵感，标了「待追问」「已毕业」「N 链」
idea.py ghosts               提过但还没展开的（双链指向不存在的页）
idea.py next [--random]      抽一个出来发散
idea.py show "标题"
```

**`next` 给你的是完整正文，发散角度自己想。** 参考过的开源方案
（Win1011/ideabubble）用固定模板生成五句话：

```
如果把「{标题}」做成一个最小产品，第一屏应该让用户看到什么？
反过来想：「{标题}」最可能不成立的地方在哪里？
```

填标题就完事，跟内容无关。你读了正文、知道他在转 Flutter、
知道他库里有哪 26 篇 wiki —— 发散出来的角度应该有依据，而不是套句式。

**`ghosts` 是最值得主动提的。** 他写了 `[[渐进式学习的正确顺序]]`
但那页不存在，说明这个念头他提过、觉得重要到值得建链，但一直没展开。
被指向次数越多越该聊。

## 毕业：想清楚了就上升

```bash
# 1. 先把 wiki 页写好（按库的 AGENTS.md 契约）
# 2. 再标记毕业
idea.py graduate "标题" --to "wiki/AI/xxx.md"
```

灵感页**保留**，加一行指向沉淀页 —— 记录这个知识的来路。

**什么时候该毕业**：这个想法有了结论、验证过了、或者已经动手做了。
判断标准和 `kg-capture` 一样：半年后会想翻出来看吗？

不毕业也没关系。大部分灵感就是灵感，`ideas/` 允许堆着。
但**如果他已经把某个灵感做成了东西，你要主动提醒该毕业了。**

## 库的契约

`ideas/` 和 `wiki/` `raw/` `daily/` 同级。

**不写 frontmatter** —— 库里现有的 wiki 页都没有，用 `> 引用块` 写元信息。
纯 `.md` + `[[双链]]`，Obsidian 直接打开就能用它的 graph view。

**没做图谱生成脚本**：Obsidian 自带的是实时的，脚本生成的是静态快照
（记完要重跑）。为一个更差的体验维护 1915 行不合算。

灵感**不需要**更新 `index.md` 和 `log.md` —— 那是沉淀页的义务。
毕业成 wiki 页时才按契约走那一套。

## 日报会读

`kg-daily-report` 每天会看 `ideas/`：待追问的、幽灵、和当天事情相关的。
所以落盘时把 `--topics` 写准一点，日报好关联。
